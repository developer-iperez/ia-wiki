Modelo de [AI9Stars](https://github.com/AI9Stars), publicado en Hugging Face como [ai9stars/G9v3-3B](https://huggingface.co/ai9stars/G9v3-3B). Es un denso causal de ~3B pensado para despliegue local y entornos con pocos recursos: asistente general, código, flujos de tool-use y razonamiento donde se prefiere un modelo compacto.

## Highlights

- **Denso pequeño con ventana grande**: 131.072 tokens de contexto nativo en un modelo de ~3B; arquitectura `LlamaForCausalLM` estándar, sin código custom.
- **Thinking conmutable**: se activa o desactiva con `enable_thinking` en el chat template, con parámetros de muestreo distintos para cada modo.
- **Tool-use declarado**: la ficha oficial lo etiqueta como `tool-calling` y lo menciona entre sus casos de uso, sin documentar un parser ni un formato concreto.
- **Compatibilidad estándar**: se sirve con vLLM (≥0.21), SGLang (≥0.5.12) o Transformers (≥5.6) sin pasos especiales.
- **Licencia permisiva**: Apache 2.0 para pesos y repositorio, según la ficha oficial y Artificial Analysis.

## Configuración recomendada

Parámetros de muestreo oficiales (ficha de Hugging Face):

| Modo | temperature | top_p | Activación |
|---|---|---|---|
| Think | 0.9 | 0.95 | `enable_thinking=True` |
| No think | 0.7 | 0.95 | `enable_thinking=False` |

- **Longitud de salida**: los ejemplos oficiales usan `max_tokens=128` para pruebas cortas. En modo thinking conviene dejar margen para el razonamiento (varios miles de tokens).
- **Thinking**: se activa desde `apply_chat_template` con `enable_thinking=True`, como en el ejemplo de Transformers de la ficha.

```bash
# vLLM (vllm>=0.21)
vllm serve ai9stars/G9v3-3B --port 8000

# SGLang (sglang>=0.5.12)
python -m sglang.launch_server --model-path ai9stars/G9v3-3B --port 30000

# Transformers
pip install -U "transformers>=5.6" accelerate torch
```

Notas:

- En el menú local de ia-lab, el GGUF de terceros [7KysYSYSysa/G9v3-3B-Q4_K_M-GGUF](https://huggingface.co/7KysYSYSysa/G9v3-3B-Q4_K_M-GGUF) (1,71 GiB) va con `--temp 0.9 --top-p 0.95 -c 131072`. Con ese GGUF el bloque `<think>` sale inline y no se separa con `--reasoning-format deepseek`, y un `max_tokens` bajo (p. ej. 32) deja la respuesta vacía; los clientes deben usar `max_tokens` ≥1024.
- Ese mismo GGUF se midió en ia-lab sin tool-calling efectivo (el modelo razona que debe llamar a una herramienta pero no emite la llamada). Es una observación de un quant de terceros, no de la ficha oficial, que sí etiqueta el modelo como `tool-calling`.
- Con el GGUF de terceros, carga completa en GPU hasta 131072 tokens requiere KV-Q4; la generación a fondo cae a ~2 t/s y el prefill de 52K tokens tarda ~16 min, así que es viable para lectura puntual de documentos largos y no para uso interactivo con contexto lleno.
